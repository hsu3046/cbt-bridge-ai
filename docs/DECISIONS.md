# CBT Bridge AI — 設計判断記録

## Decision Log

### D-001: 分割ビュー — 同URL方式の採用

**日付:** 2026-03-12  
**背景:** 分割ビューを実装する方法として3つの候補があった。

| 方式 | Pros | Cons |
|------|------|------|
| Chrome Native Split View API | OS統合 | Chrome 143+限定、API未公開 |
| カスタムHTML翻訳パネル | 完全制御可能 | レイアウト不一致、比較不可 |
| **同URL + 全文翻訳 (採用)** | 同じデザイン/レイアウト、比較容易 | 2回ページロード、API消費 |

**決定:** 同じURLを新ウインドウで開き、Content Scriptで全文翻訳する方式。  
**理由:** 原文と訳文を同じレイアウトで比較できる点が学術翻訳において最重要。

### D-002: チャンク翻訳によるコスト制御

**日付:** 2026-03-12  
**背景:** 全文翻訳で407段落（Cookie含む）を一括処理した結果、不要テキストの翻訳でAPI料金が発生。

**決定:**
1. 10段落ずつ翻訳 → 確認ダイアログ表示
2. 本文領域の自動検出 (`<article>` → `<main>` → テキスト密度)
3. 20+パターンの除外フィルター

**理由:** ユーザーが「続行/停止」を選択できることで、コストの予測可能性を確保。

### D-003: 3モデルハイブリッドルーティング

**日付:** 2026-03-12  
**背景:** 全ての翻訳にPro (最高品質) を使うとコストが高すぎ、Flash Lite だけでは核心セクションの品質が不足。

**決定:**
- `low` (ホバー) → Flash Lite ($0.25/1M)
- `normal` (通常) → Flash ($0.50/1M)  
- `high` / 核心セクション → Pro ($2.00/1M)

**理由:** 品質要求に応じたモデル選択で、コスト対品質比を最適化。

### D-004: クリックで原文/訳文トグル

**日付:** 2026-03-12  
**背景:** 翻訳結果を表示する方法 — ツールチップ vs フローティング vs インライン置換。

**決定:** 翻訳テキストで原文を直接置換。クリックで原文に戻る。  
**追加:** `event.preventDefault()` でリンク内段落のクリック時にページ遷移を防止。

**理由:** 最もシンプルで自然。ツールチップは表示位置の問題、フローティングは画面占有の問題がある。

---

### D-005: ランタイム依存ゼロ

**日付:** 2026-03-12  
**背景:** Chrome拡張のバンドルサイズとセキュリティを考慮。

**決定:** ランタイム依存なし。全てブラウザ標準API + Gemini REST API のみ。  
**理由:** バンドルサイズ最小化、サプライチェーン攻撃リスクの排除、Chrome拡張審査の簡素化。
